# Rider Rate Card & Settlement Architecture — Phase 1

## 1. Purpose
กำหนดหลักการคำนวณค่ารอบ Rider และการ Settlement โดยแยกค่าจัดส่งที่เรียกเก็บออกจากเงินที่ Rider ได้รับ

## 2. Base Rate
**15 บาท / รอบ สำหรับ 5 กม.แรก** ในวันและเวลาปกติ

หลักนี้ถือเป็น Rate Card ที่ตกลงแล้วสำหรับการออกแบบระบบ และไม่ควรย้อนกลับไปเปลี่ยนเรทในขั้นตอนถัดไปโดยไม่มีการเปลี่ยนแปลงนโยบายอย่างเป็นทางการ

## 3. Payer
ค่ารอบที่เรียกเก็บ:
- ร้านค้า: 50%
- ผู้สั่งอาหาร: 50%

ตัวอย่าง Base 15 บาท:
- ร้านค้า 7.50 บาท
- ผู้สั่ง 7.50 บาท

## 4. Distance
ใช้ **ระยะทางถนนจริงของ Trip** ไม่ใช้ระยะเส้นตรง

สำหรับงานเดี่ยว:
- จุดอ้างอิงเส้นทางต้องสะท้อนการเดินทางจริงของ Rider

สำหรับงานซ้อน:
- คำนวณจากเส้นทางที่ Rider วิ่งจริง/เส้นทางที่ระบบเลือก
- ประเมินระยะทางที่เพิ่มขึ้นจากการเพิ่ม Order
- ห้ามคิดงานซ้อนเหมือนเป็นการนำค่ารอบเต็มของแต่ละ Order มาบวกกันโดยอัตโนมัติ

## 5. Vehicle Baseline
ใช้รถจักร **150 cc เป็น Baseline** เนื่องจากบริบทพื้นที่มีเนินเขาและความลาดชัน

ต้นทุนรถแยกเป็น:
- ค่าน้ำมัน
- ค่าเสื่อม
- ค่าบำรุงรักษา/ชิ้นส่วนสึกหรอ ตามนโยบายต้นทุนของระบบ

## 6. Rider Compensation
หลักการคำนวณ:
> ค่าตอบแทน Rider ต้องแยกจากค่าจัดส่งที่เรียกเก็บจากร้านค้า/ผู้สั่ง

ระบบจึงต้องมีอย่างน้อย:
- Delivery Fee / เงินที่เรียกเก็บ
- Rider Payout / เงินที่ Rider มีสิทธิ์ได้รับ
- Rider Pool / กองกลาง ตามนโยบายที่กำหนด

## 7. Rider Pool
ส่วนต่างระหว่างเงินที่เรียกเก็บกับ Rider Payout สามารถนำเข้ากองกลาง Rider ตามโครงสร้างที่ตกลงกัน

ตัวอย่าง:
- Delivery Fee = 15 บาท
- Rider Payout = 10 บาท
- ส่วนต่าง = 5 บาท
- 5 บาท → Rider Pool

กองกลางมีวัตถุประสงค์เพื่อสนับสนุน Rider เช่น Bonus/การช่วยเหลือ/กรณีพิเศษ ตามกติกาของกลุ่ม

## 8. Rider Group
แนวคิดการบริหารกองกลาง:
- มีกลุ่ม Rider
- มีกลุ่ม/บัญชีกลาง
- มีประธานกลุ่ม
- มีผู้รับผิดชอบตามกติกาของกลุ่ม
- รายการรับ–จ่ายต้องตรวจสอบได้

Platform ไม่ควรถือเงินกองกลางไว้เป็นเงินของ Platform หากโครงสร้างทางกฎหมายกำหนดให้เป็นเงินของกลุ่ม

## 9. Daily Settlement
กำหนดให้มีการสรุป Settlement รายวัน

Flow:
Order สำเร็จ
→ คำนวณ Delivery Fee
→ คำนวณ Rider Payout
→ คำนวณยอด Rider Pool
→ สร้าง Daily Settlement
→ Settlement ผ่าน Payment Provider
→ เงินของกลุ่มเข้าบัญชีกลางตามสิทธิ์

ควรมี Daily Settlement Report:
- จำนวน Order
- Delivery Fee รวม
- Rider Payout รวม
- Rider Pool รวม
- รายการอ้างอิง Order
- ยอดสะสม

## 10. Payment Architecture
เพื่อหลีกเลี่ยงการให้ Platform ถือเงินของหลายฝ่ายโดยไม่จำเป็น:

> ให้ Payment Provider ที่เหมาะสมเป็นผู้รับเงิน/พักเงินและทำ Settlement

Platform ทำหน้าที่:
- คำนวณสิทธิ์
- สร้าง Settlement Instruction
- บันทึก Ledger/Report
- ตรวจสอบสถานะ Settlement

ก่อนใช้งานจริงต้องตรวจสอบรูปแบบธุรกรรมกับผู้เชี่ยวชาญด้านกฎหมาย Payment, บัญชี และภาษีของไทย

## 11. Special Conditions
ค่ารอบปกติแยกจาก Bonus/Adjustment เช่น:
- ฝนตก
- สภาพการณ์พิเศษ
- งานที่มีต้นทุนสูงกว่าปกติ

Rain Bonus เป็นเงินเพิ่มจากค่ารอบปกติ และไม่ควรแก้ Base Rate

## 12. Rate Card Lock
Rate Card ที่ตกลงใน Phase นี้:
- Base 15 บาท / 5 กม.แรก
- ร้านค้าและผู้สั่งจ่ายคนละครึ่ง
- ใช้รถ 150 cc เป็น Baseline
- งานซ้อนต้องคำนวณตามภาระและเส้นทางจริง
- กองกลาง Rider แยกจากเงิน Platform
- Settlement รายวัน

**หมายเหตุ:** ตัวเลขเฉพาะของต้นทุนต่อกิโลเมตรที่ยังไม่ได้เคาะ ไม่ควรถูกแต่งขึ้นในเอกสารนี้ ให้ใส่เป็น Configuration/Parameter เมื่อมีข้อมูลต้นทุนที่ยืนยันแล้ว
