# รายการตรวจสอบสิ่งที่ต้องดำเนินการด้านกฎหมาย (Legal & PDPA Compliance Checklist)

> **ระบบ:** RAN-R-HAN (รับอาหาร) — ระบบสั่งอาหารออนไลน์และจัดการร้านอาหาร Multi-tenant SaaS  
> **สถานะ:** เอกสารสรุปความพร้อมและการปฏิบัติตามกฎหมาย (Legal Compliance Action Items)  
> **ปรับปรุงล่าสุด:** 2026-09-10  

---

## 📌 บทสรุปภาพรวม

ปัจจุบันระบบ RAN-R-HAN มีชุดเอกสารกฎหมายหลักครบถ้วนในรูปแบบฉบับร่าง (DRAFT) ได้แก่:
1. **ข้อกำหนดและเงื่อนไขการใช้บริการ (Terms of Service - ToS)**
2. **นโยบายความเป็นส่วนตัว (Privacy Policy ตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562)**
3. **แนวทางการแก้ไขแอปพลิเคชันเพื่อรองรับกฎหมาย (Engineering Roadmap: WP-19 ถึง WP-24)**

เพื่อให้ระบบมีความพร้อมในการใช้งานจริงและสอดคล้องกับกฎหมายอย่างสมบูรณ์ จำเป็นต้องดำเนินการตาม 4 หมวดงานด้านล่างนี้:

---

## ⚖️ หมวดที่ 1: รายการที่ต้องส่งตรวจรับรองโดยทนายความและนักบัญชี

| ลำดับ | ประเด็นที่ต้องตรวจสอบ | ความเร่งด่วน | รายละเอียดและสิ่งที่ต้องการคำยืนยัน |
| :---: | :--- | :---: | :--- |
| **1.1** | **ชี้ขาดสถานะ Controller vs. Processor ของแพลตฟอร์ม** | 🔴 สูงสุด | สรุปสถานะของ RAN-R-HAN ภายใต้ PDPA ว่าเป็น **ผู้ประมวลผลข้อมูล (Processor)** หรือ **ผู้ควบคุมข้อมูลร่วม (Joint Controller)** ร่วมกับร้านค้า เพื่อจัดทำสัญญา **Data Processing Agreement (DPA)** แนบท้ายสัญญา B2B |
| **1.2** | **ความชอบธรรมของข้อมูลพรีออเดอร์จาก Facebook Comment** | 🔴 สูงสุด | การนำเข้าข้อมูลลูกค้าจากคอมเมนต์สาธารณะ (กาดแม่ฮ่องสอน) เป็นการได้ข้อมูลจากแหล่งอื่น (ม. 25 PDPA) — ต้องให้ทนายยืนยันว่าข้อความ Consent สั้นในโพสต์เพียงพอหรือไม่ และแนวปฏิบัติของพนักงานชอบด้วยกฎหมายหรือไม่ |
| **1.3** | **การทดสอบความสมดุล (Balancing Test) ฐาน Legitimate Interest** | 🟠 ปานกลาง | ยืนยันความชอบธรรมในการเก็บข้อมูลธุรกรรมเพื่อป้องกันการฉ้อโกงและตรวจสลิปซ้ำ/สลิปปลอม |
| **1.4** | **ข้อจำกัดความรับผิดในข้อกำหนดการใช้งาน (ToS)** | 🟠 ปานกลาง | ปรับปรุงข้อจำกัดความรับผิดใน ToS ข้อ 8 ให้รัดกุม ไม่ขัดต่อ พ.ร.บ. คุ้มครองผู้บริโภค และ พ.ร.บ. ข้อสัญญาที่ไม่เป็นธรรม |
| **1.5** | **ระยะเวลาการจัดเก็บข้อมูลทางบัญชีและภาษี** | 🟠 ปานกลาง | ให้นักบัญชียืนยันประเภทเอกสารที่เข้าข่ายเอกสารประกอบการลงบัญชี (ต้องเก็บอย่างน้อย 5 ปี ถึง 7 ปี) เทียบกับ Operational Data ที่ต้องลบตามนโยบาย PDPA |

## 🏢 หมวดที่ 2: ข้อมูลที่เจ้าของร้าน / ผู้ประกอบการต้องระบุเอง (`[ต้องกรอก]`)

- [ ] **ข้อมูลผู้ควบคุมข้อมูลส่วนบุคคล:** ชื่อนิติบุคคล/ชื่อร้านค้า, เลขประจำตัวผู้เสียภาษี, ที่อยู่จดทะเบียน
- [ ] **ช่องทางติดต่อด้านสิทธิข้อมูลส่วนบุคคล:** อีเมลและเบอร์โทรศัพท์สำหรับรับเรื่องขอใช้สิทธิตาม PDPA
- [ ] **นโยบายการคืนเงิน (Refund Policy):** ระบุกรอบเวลาและขั้นตอนการโอนเงินคืน กรณีลูกค้ายกเลิกคำสั่งซื้อที่จ่าย PromptPay ไปแล้วก่อนที่ร้านจะเริ่มปรุงอาหาร
- [ ] **สถานะภาษีมูลค่าเพิ่ม (VAT):** ระบุว่าร้านจดทะเบียน VAT หรือไม่ เพื่อกำหนดข้อความการเก็บรักษาใบกำกับภาษี
- [ ] **นโยบายการตลาด:** ยืนยันว่าจะไม่มีการนำข้อมูลเบอร์โทรศัพท์ไปทำการตลาด (Marketing/SMS) หากมี ต้องจัดทำ Consent Form แยกต่างหาก

## 💻 หมวดที่ 3: แผนงานพัฒนาทางเทคนิคในระบบ (Technical Roadmap: WP-19 ถึง WP-24)

### [x] WP-19: สร้างหน้าเว็บจริงสำหรับ Privacy Policy และ Terms of Service (เสร็จสิ้น ✅)
- [x] สร้าง Route `/terms` และ `/privacy` (ระดับแพลตฟอร์ม)
- [x] สร้าง Route `/[slug]/terms` และ `/[slug]/privacy` (ระดับร้านค้า แสดงชื่อและข้อมูลผู้ควบคุมข้อมูลจริง)
- [x] เพิ่มลิงก์นโยบายในส่วนท้าย (Footer) ของหน้าแสดงเมนูอาหาร (`MenuClient.tsx`)

### [x] WP-20: จุดขอความยินยอม (Consent UI) และการบันทึกหลักฐานการยินยอม (เสร็จสิ้น ✅)
- [x] เพิ่ม Checkbox บังคับ: *"ยอมรับข้อกำหนดการใช้งานและนโยบายความเป็นส่วนตัว"* ก่อนปุ่มยืนยันสั่งซื้อในหน้า Checkout (`CheckoutClient.tsx`)
- [x] สร้าง Database Migration ตาราง `consent_logs` เก็บ Timestamp, เวอร์ชันนโยบาย (2026-09-10), ประเภทความยินยอม และ IP/User-Agent
- [x] บันทึก Timestamp การให้ความยินยอมเมื่อผู้ใช้กดอนุญาตแชร์ตำแหน่ง GPS (ปุ่ม Get GPS) ส่งเข้า `consent_logs`

### [x] WP-21: ระบบ Audit Log สำหรับการนำเข้าพรีออเดอร์จาก Facebook (เสร็จสิ้น ✅)
- [x] บันทึก Audit Log ลงตาราง `audit_logs` ทุกครั้งที่มีการนำเข้าคอมเมนต์ Facebook ใน `delivery.ts` (`addBulkPreorderItemsAction`)
- [x] เพิ่ม UI Notice Banner ในหน้าเปิดรอบพรีออเดอร์ แนะนำข้อความแจ้ง Consent สำหรับแปะในโพสต์ Facebook ก่อนเปิดรับคอมเมนต์

### [x] WP-22: ระบบลบหรือทำลายข้อมูลอัตโนมัติ (Automated Data Retention) (เสร็จสิ้น ✅)
- [x] สร้าง Endpoint `/api/cron/data-retention` พร้อมการตรวจสอบสิทธิ์ `CRON_SECRET`
  - [x] ลบออเดอร์ที่ยกเลิก/ไม่ชำระเงิน ที่มีอายุเกิน 90 วัน
  - [x] ล้างข้อความดิบ (`raw_input_text`) จากคอมเมนต์ Facebook เก่ากว่า 90 วัน
  - [x] ลบ Audit Log เก่ากว่า 1 ปี
  - [x] คุ้มครองข้อมูลบิลที่ชำระเงินสำเร็จ (5-7 ปีตามกฎหมายภาษี)

### [x] WP-23: กลไกรองรับการใช้สิทธิของเจ้าของข้อมูล (Data Subject Rights) (เสร็จสิ้น ✅)
- [x] จัดเตรียมแบบฟอร์มคำขอใช้สิทธิ 8 ประการตาม PDPA (`DataSubjectRequestForm.tsx`) ฝังในหน้า `/privacy` และ `/[slug]/privacy`
- [x] สร้างตาราง `data_subject_requests` บันทึกคำขอพร้อมระบบคำนวณ Due Date 30 วันตามมาตรา 30 แห่ง พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
